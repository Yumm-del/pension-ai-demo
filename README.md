# 工银智养仓 · B端运营工作台 v4.0

第17届工行杯参赛原型。面向个人养老金客户经理，使用200位程序生成的模拟客户，展示从服务准备到回访的流程。

## 本地运行

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

保留现有 Streamlit 部署方式，入口仍是 `app.py`。无需配置 API Key 即可演示全部流程；可选 DeepSeek 仅对固定模板进行措辞改写，不上传姓名、薪资、客户回访自由文本。生成稿仍须规则预检和人工审核。

## 三分钟演示顺序

1. 今日工作台：查看待联系、待审核/发送、待回访、暂缓联系名单；按任务状态与未操作天数排序。
2. 客户分型：选择 C1000 陈女士，查看“规则认知不足”的模拟主动反馈及下一步。
3. AI策略工场：生成候选话术。问候语可以修改，规则正文与风险提示锁定。在问候语中加入“保本”可演示拦截，恢复正常问候后保存。
4. 填写模拟审核人并勾选核对，确认人工审核后模拟发送。修改已审核文本会撤销审核；已发送版本不能再修改。
5. 回访中选择“暂不参与”，原因选择“当前现金流受限”，填写模拟反馈。保存后客户库与分型同步更新，系统停止该客户的主动联系。
6. 合规中心：查看候选原稿、经办修改版、实际模拟发送版、差异和时间线，导出 JSON 记录。

其他固定情景：C1001 资金锁定顾虑；C1002 当前现金流受限；C1003 操作求助；C1004 原因待确认；C1005 67岁客户规则解释。字段来源均为人为设置的演示情景，不代表实际调研参与者。

## 实现状态

| 能力 | 当前实现 |
|---|---|
| 证据分型 | 五类服务原因，明确反馈优先，知识测评信号待复核，信息不足不强行归类 |
| 任务流程 | 草稿 → 自动规则预检 → 模拟人工审核 → 模拟发送 → 回访 |
| 版本控制 | 候选原稿冻结、编辑快照、审核文本指纹、发送版冻结、事件记录 |
| 回访修正 | 更新客户原因、记录下一步；拒绝后停止联系，预约到期前暂停 |
| 批量任务 | 最多10位创建独立草稿，逐条审核，不批量自动发送 |
| 税优测算 | 综合所得逐档税额差，支持年度应纳税所得额或月薪及扣除项输入 |
| A/B试验台 | 试点设计与指标口径，尚无真实经营效果 |
| 生产能力 | CRM、真实角色权限、合规规则准入、持久化归档、触达接口待接入 |

任务与修改仅保存在当前 Streamlit 会话中。刷新、断开会话或服务重启可能丢失；可在合规中心导出。审核人是演示输入，不代表已实现银行级身份认证、权限隔离或不可篡改审计。所有“发送”均为模拟，没有实际发出任何消息。

## 税优口径

当年减税 = 扣除前综合所得税额 − 扣除后综合所得税额。每年抵扣限额12,000元，未来领取环节的3%税款单独说明，不从当年节税中扣除。

- 扣除前应纳税所得额240,000元、缴存12,000元：当年减税2,400元。
- 扣除前应纳税所得额40,000元、缴存12,000元：跨档减税640元。
- 扣除前应纳税所得额36,000元、缴存12,000元：当年减税360元，不是0元。

政策依据：https://fgk.chinatax.gov.cn/zcfgk/c102416/c5237110/content.html
本工具仅用于综合所得简算；实际税务结果以税务机关核定为准。

## 代码与验证

- `app.py`：既有品牌样式、模拟客户初始化、导航及A/B试验台。
- `operations.py`：独立可测试的税额、分型、内容预检与任务状态规则。
- `workbench.py`：工作台、客户详情、审核回访、客户库和税优界面。
- `test_operations.py`、`test_app.py`：业务边界与 Streamlit AppTest 交互测试。

```powershell
python -m unittest -v test_operations.py test_app.py
```

原 `engine_eval` 目录针对旧三分类规则，其评估结果不适用于当前五类服务原因；新版需要重新建立标注集。
